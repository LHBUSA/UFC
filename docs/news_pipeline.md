# News pipeline (Track B)

Three plain-Node scripts in `scripts/news/` (no npm deps; `.env` supplies `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`). Shared helpers live in `scripts/news/lib.mjs`. The article writer implements `docs/UFC_PRODUCTION_V3_EDITORIAL_ADDENDUM.md` and produces the fact block defined in `docs/editorial_contract.md`.

## Sources (`ufc_news_sources`)
- RSS: MMA Fighting (`/rss/index.xml`, Atom), ESPN MMA (`/espn/rss/mma/news`), UFC.com News (`/rss/news`). Verified live by `seed_sources.mjs` before every upsert.
- Dropped at seed time because the feed does not verify: MMA Junkie (`/feed` 404), Bloody Elbow (`/feed` returns 403 to Node's fetch). A seeded source whose feed stops verifying is disabled, never deleted.
- `internal` / `propbetedge-tables` (weight 2): the source of every story built from our own tables.

## Cadence (from the brief; event-aware, never fake-hourly)
- Fight week (Mon-Sat of a card): `ingest_news.mjs` every 30 min, `write_articles.mjs` right after; publish as stories qualify, cap ~2/hr. Previews for the next two cards exist all week and refresh only when their fact block changes.
- Off weeks: ingest every 2 h; 3-6 stories a day is the ceiling, and an empty run is the correct output when nothing qualifies. Do not pad.
- Results stories are written the first run after results land (Saturday night / Sunday); add `--relink` to the next ingest so fight-week items pick up fighters and bouts that were loaded after they were captured.

## Running
1. `node scripts/news/seed_sources.mjs [--dry-run]` - verify feeds, upsert sources on `(kind, name)`. Idempotent.
2. `node scripts/news/ingest_news.mjs [--dry-run] [--max-age-days 14] [--relink]` - pull enabled RSS sources -> `ufc_news_items` (dedupe by `url` and `fingerprint`, classify, link fighter/event/bout). Prints per-source and total counts.
3. `node scripts/news/write_articles.mjs [--dry-run] [--types preview,results,external,card_change] [--limit N] [--llm] [--print] [--force] [--event <name>]` - builds fact blocks from our tables, then prose -> `ufc_articles`. `--print` dumps every created/refreshed article with its `bettor_angle` and `market_watch` JSON. `--force` re-renders preview/results rows whose fact-block hash is unchanged (use after a template or prose fix; the gates still apply). `--llm` (needs `ANTHROPIC_API_KEY`) rewrites the template draft with `claude-sonnet-5` (adaptive thinking; raw Messages API because the scripts carry no npm dependency and CI runs them without an install step) for flow and matchup translation only. The rewrite must pass the same gates as the template plus structural checks (no number outside the draft, headings / list lines / links unchanged, length within 15%) or the template is kept. `model_version` records `template-2` or the model id. The run ends with `created / refreshed / unchanged / held_for_review` counts and a word-count table by `story_class`.

## Article anatomy (fact block v2)
Every story stores `fact_block` exactly as `docs/editorial_contract.md` defines it: `version: 2`, `story_class`, `generated_at`, `sources.families`, `event`, `bout`, `matchup { a, b, edges[] }` (FighterFacts: record, age, height, reach, stance, listed weight, `career` UFC Stats averages with percentages normalised to printed form, `archive` with W/L/D/NC, KO/SUB/DEC split, finish rate on wins, round-stat totals labelled by `rounds_with_stats`, last 5 results and `days_since_last` measured to the event date so a daily run does not churn the hash), `bettor_angle`, `market_watch`, and `results` for results stories. Additive keys the writer also stores: `depth { class, target, short, short_reason }`, `bettor_angle.rules_applied`, `archive.finishes / finished_by / r1_finishes`, `results.post_mortem`.

`story_class` and depth targets (words, headings excluded): `main_event_preview` 900-1,500 · `main_card_preview` 650-1,050 · `prelim_preview` 300-700 · `results` 800-1,400 · `card_change` 500-900 · `external` 250-500. Depth is data-led: when the block cannot support the range (no UFC Stats averages for a fighter, an archive shorter than 3 bouts, reach missing, no round stats for a results main event) the writer sets `depth.short = true` with the reason and writes the concise version instead of padding. A short story must still clear a floor (450 / 350 / 180 / 400 words for the four classes above).

Preview markdown uses the contract's fixed H2s in order, omitting any section the block cannot support: `## The setup` (event, venue, position, rounds, records, the analytical question), `## Tale of the tape` (list plus implication prose: what a reach gap is worth given pace, stance geometry, age read with layoff), `## Recent form` (archive paragraph and last-5 list per fighter, then a comparative read on activity and finishing profiles), `## Style and statistical matchup` (SLpM/SApM/defence/takedown interaction when career averages exist for both; one-sided description when only one fighter has them; round-stat totals and method mix as the fallback style signal), `## What could break the angle`, `## Final read`, then internal links. Results stories use `## Main event` (result, pre-fight archive context, pre-fight tape, last-3 form strips), `## Full results`, `## By the numbers` (when round stats exist) and `## What the fight changed` (validated/challenged profile, round-stat differentials, distance outcome and archive pattern after the result, markets to reassess). The Bettor's Edge block and the Market watch box are NOT in the markdown; the page and the API render them from `fact_block.bettor_angle` / `fact_block.market_watch`. The old "Algo lean: locked" hook is gone: the page renders its own Pro lock.

Headlines are evidence-led only when a real edge exists (reach and pace both favouring one side; a takedown-rate vs takedown-defence mismatch; a reach edge of 4"+; one or two finishers on 3+ archived wins; a five-round main event with archives on both sides), otherwise a plain matchup headline. Deks state the analytical question.

## Bettor angle rules (analysis, derived only from the fact block)
Impact score, previews: start 1; +1 title fight or main event; +1 five scheduled rounds; +1 material mismatch (reach >= 3", or SLpM gap >= 1.5, or TD avg >= 1.5 per 15 against TD defence <= 65%); +1 finish-rate signal (either fighter >= 60% on >= 3 archived wins); -1 thin sample (either fighter < 3 archived bouts and no career averages); capped at 3 when neither fighter has UFC Stats averages and at 4 when only one has; clamped 1-5. Results: start 2; +1 title fight; +1 five scheduled rounds; +1 finish inside two rounds; +1 large round-stat differential (>= 40 significant strikes, >= 4:00 control or >= 2 knockdowns); -1 no round stats. Card changes: 2, or 3 for a replacement at <= 14 days' notice. External wire items: 1, or 2 when a booking-affecting label touches a scheduled bout. `rules_applied` records which fired.

Markets are listed only when logically connected: five rounds -> `total_rounds`; a finish-rate signal or a fighter finished twice or more -> `fight_goes_distance` + `method_of_victory`; both fighters <= 34% finish rate on 3+ wins -> `fight_goes_distance`; takedown mismatch -> `takedowns`; SLpM gap >= 1.5, both >= 4.5, or a 3"+ reach edge with pace data -> `significant_strikes`; two or more first-round finishes -> `round_betting`; `moneyline` only when two or more directional edges favour the same side and none the other. `market_watch.markets` is the same list without moneyline (max 3), defaulting to distance + total rounds.

Every angle carries >= 1 supporting fact (edge notes, finish rates, takedown numbers, the five-round fact, or records as the floor), >= 1 risk (thin archive, missing career averages, incomplete grappling metrics, missing reach, short notice, a layoff over a year, the career-snapshot caveat, and always the absence of an odds snapshot) and watch items (weigh-in, five-round or card-position confirmation, line movement once priced). `odds_status` and `model_status` are always `unavailable`; the gates reject anything else because no odds table or model output exists.

Edges (`matchup.edges`) are material differences only: reach and height >= 2", age >= 5 years (favours the younger), SLpM / SApM >= 1.0, striking defence >= 8 points, TD avg >= 1.0, TD defence >= 10 points, finish rate >= 25 points on 3+ wins each, archive depth >= 3 bouts.

## Editorial gates (addendum §11, in code; fail closed)
Run on the template draft and on any LLM rewrite. A template draft that fails is stored with `status='review'`, `needs_human=true` and `fact_block.review_reason`; an LLM rewrite that fails is discarded and the template kept.
- Depth: words >= the story-class minimum, or the short floor when `depth.short` is set.
- Numbers: every number in headline, dek and body must appear in the fact block (plus feet/inches of a listed height, zero-padded date parts, and the counts 0-5, 15, 25).
- Language: no American-odds prices, favourite/underdog, lock/guaranteed, pick/prediction/will win, probability/chance/parlay/wager, sportsbook names, odds or line quotes; no injury language unless the story is an external item whose attributed label is injury/withdrawal.
- Bettor angle: integer impact 1-5, known markets only, >= 1 supporting fact, >= 1 risk, odds/model status `unavailable`; `market_watch.status` `unavailable`.
- Internal links resolve to slugs the site builds (`/events/<eventSlug>`, `/fighters/<fighterSlug>`, `/fights/<matchupSlug>`, `/news/<slug>`).
- Duplicate slug within a run; near-duplicate headline (token Jaccard >= 0.9) against the run and existing rows; headline <= 140 characters.
- Licensed media: a hero without complete `{author, license, source_url}` is dropped (the site renders its own stat card) rather than published uncredited.

## Review queue
`select * from ufc_articles where status = 'review'` (all have `needs_human = true`). Rows held by a gate carry `fact_block->>'review_reason'`; a refresh whose block then passes re-publishes them. Rows an editor placed in review (no `review_reason`) are never promoted or demoted by a refresh. Every `external` story whose qualifying label is `injury` or `withdrawal` and that names a fighter is held for review. Publishing is a manual flip of `status` to `published` (set `published_at`). `external` and `card_change` stories are never regenerated once written.

## Rule set (non-negotiable)
- Every story is generated from a stored `fact_block` built from `ufc_events`, `ufc_bouts`, `ufc_bout_results`, `ufc_bout_round_stats`, `ufc_fighters`; prose may not state anything outside that block or the cited news item. `sources` carries the fact-block hash (`{kind:'fact_block', hash, version}`), the tables used and any `news_item` id.
- No FABRICATED odds, picks, probabilities or predictions. Betting-impact analysis is required when the verified block supports it and is stored in `bettor_angle`, labelled as analysis. Prices and model outputs may appear only when those fields exist in verified structured data (none do yet).
- External reporting: one quoted phrase (max six words of the title), source named and linked, everything else from our tables; items that link no fighter produce no story.
- Idempotent: a slug is never created twice; `results` / `fight_preview` refresh only when the salted fact-block hash changes (`factHash(block, {salt: 'v2'})`, `generated_at` excluded, `updated_at` bumped). Bumping the salt regenerates every stored preview/results article once.
- Hero image: `ufc_images.id` of the subject fighter's Wikimedia portrait with `{author, license, source_url}` copied into `hero_credit`; null when none exists or the credit is incomplete. Never UFC/Zuffa/Getty/ESPN/Sherdog imagery.

## Known data limits (2026-09-06)
UFC Stats career averages exist for 53 of 867 fighters (one fighter on each of the next two cards), and round stats for 24 bouts, so nearly every preview runs `depth.short` with the reason recorded and the Style section falls back to round-stat totals or the method mix. Results main events on the last four cards have no round stats, so their post-mortems rest on the result and the archive. Impact scores are capped accordingly; depth rises automatically as coverage does.
